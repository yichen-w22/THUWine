# 推送制作工作流

使用同目录 `theme.json`、`scripts/post_builder.py`，项目的 `正文.md`（唯一文字源）与 `post.json`（布局及素材）。常规任务不需要重写程序。

1. **收齐内容与来源。** 用户指定文案、图片、总体风格和顺序。核对所有酒款，尤其是额外提供的白葡萄酒；酒单数量从结构化条目计算。扫描或图片中的介绍要提取成独立文字，不把大段文字当作整张海报嵌入。人物姓名、酒名、活动地址、收费与退款规则有冲突时，依据用户最新明确指示处理；不能推断时保留待确认。
2. **建项目并归档素材。** `python scripts/post_builder.py new <项目名> --title "标题"`。将图片复制入项目 assets，填写来源说明；不要移动或修改用户原素材。复用公用 logo，但不能默认继承上一活动的赞助关系、时间、费用或主讲人。
3. **填内容，调用组件。** 新建项目会产生正文Markdown。按用户顺序组织 sections，每个 section 对应一张最终图片；新增组件可先在post.json填写字符串，执行 `markdown-refresh` 会保留旧正文并把新字段合入Markdown。后续文字只改正文.md，保留隐藏的pb-text注释。旧JSON项目用 `markdown <项目名>` 一次性迁移。参数见 `WORKFLOW.md`。
4. **核对并生成网页。** 运行 `check` 与 `preview`。打开返回的 HTML 预览。文本应保持可选中，便于浏览器批注；不要先烘焙成一张图片。生成网页不需要批准。批注中选区和截图是定位证据，用户的 Comment 才是修改要求。
5. **迭代同一预览。** 文字批注改到正文.md，布局批注改配置，保留block id。用户直接编辑时用 `serve <项目名>` 启动本地自动预览，显示返回的HTTP地址；用户在Typora保存后自动更新，无需每次请求Codex修改。只监听127.0.0.1。报错保留上次有效页面；不自动导出图片。正常版本有正文历史备份。
6. **确认后导出。** 只有当前网页得到用户明确确认后，运行 `approve <项目名> --note "用户的实际确认指令"`，然后 `export <项目名>`。输入、图片、字体、样式或排版程序变化都会使旧确认失效。不是通过伪造 approval 文件跳过流程。
7. **交付。** 核对图片数量与宽度、拼接连续性、酒款完整性、段首段尾及文末提示。只交付用户需要的分段图片，按编号排列。

## 命令位置

在本目录执行，`<项目名>` 为 `projects/` 下的目录名：

```powershell
python scripts/post_builder.py check <项目名>
python scripts/post_builder.py preview <项目名> --note "本次实际修改"
python scripts/post_builder.py serve <项目名>
python scripts/post_builder.py stop <项目名>
python scripts/post_builder.py approve <项目名> --note "用户的实际确认指令"
python scripts/post_builder.py export <项目名>
```

如果预览打开成源码，用应用的“打开文件/浏览器预览”切换到渲染视图。若自动读取 file URL 被浏览器策略阻止，不尝试绕过：用户仍可在其预览里批注；从本地源文件修改，使用确定性导出和本地图像检查。

## 字体与组件的边界

- 固定字体为宋体标题、等线 Light 正文；具体角色与数值以 `theme.json` 为唯一来源。
- 主标题、普通分节、酒款名称默认深酒红；温馨提示、特别鸣谢和结语黑色。品牌原 logo 不强制染色。
- 1080px 是图片画布宽度，不是手机上的 CSS 像素；不要按手机宽度重写字号。
- 要更换风格时，先与用户确认是“仅这篇”还是“今后默认”；不要无意改掉所有项目共用主题。
- 工作区工作流已建立，不代表已安装为全局 Codex 技能。用户从其他聊天调用时可给出本目录路径；不要自动修改用户全局技能目录。
